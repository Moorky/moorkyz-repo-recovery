# Decision 0003 - SQLite case workbench and paired subjective estimates

Date: 2026-10-30. Status: implemented.

The owner clarified that component directories are not repositories, requested
lifecycle/findings/outcome columns, paired potential/current estimates,
relational recovery ratios beyond 100%, SQLite and actual fix scripts. They
also requested timestamped procedure history with a 0-100 helping factor.

Replace directory-candidate classification with independent project/Git-root
discovery. Ordinary README-only directories and monorepo package folders are
not separate cases unless they own Git metadata.

Use built-in Node SQLite (22.13+) with transactional workspace, repository,
event, evidence and procedure records. Import legacy JSON once without editing
the source. Keep all runtime data outside scanned/project roots.

Group table cells instead of adding a wide separate column for every timestamp.
Use a continuous red/coral/amber/sage/mint percentage palette, accessible column
tooltips, and paired potential/current grids. Estimates remain subjective even
when informed by measurements. Recovery scenario = condition × relative quality
/ 100; confidence is independent. Known-file retention remains separate evidence.

Actual medikit fixes are limited to baseline-file restoration, UTF-8 line-ending
normalization and exact local Markdown-link repair in verified disposable copies.
Each requires a preview/hash approval and invalidates subsequent quality/recovery
evidence. No generic arbitrary-shell execution or automatic history rewriting.

Procedure helping factors require reviewed rationale and are not fabricated from
exit codes. Lifecycle decisions need final reports; delivery also needs recovery
validation. No automatic Git commits or deployment are included.
